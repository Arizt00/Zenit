# R12 verification

Source verification on Windows x64, 15 October 2026:

- `npm run check`: JavaScript syntax checks passed.
- `npm test`: 113 tests passed.
- `python -m unittest discover -s tests -p 'test_*.py' -q`: 370 tests,
  successful, with nine environment-dependent or opt-in tests skipped.
- `python -m unittest tests.test_build_cleanup -q`: one additional Windows
  regression passed after the full run. It checks replacement of read-only SDK
  output and rejects cleanup outside the build directory.
- `python tests/check_workflow_r12_ui.py --output tests/visual/r12`: twelve
  checks passed against the actual backend and Monaco in headless Edge;
  no browser page errors. Screenshots and the check list are in that directory.
- The opt-in live QEMU test passed separately, including a second boot: Arch
  reached its serial console, wrote a guest file, saved its descriptor, stopped,
  reopened and read the same file from the restored disk. The complete two-boot
  test took 383.8 seconds. An earlier run hit a 240-second first-boot deadline;
  the software-virtualization test now allows 420 seconds for each boot. This
  does not verify a RAM snapshot or cross-computer migration.

The browser checks cover Settings-only connections, cancellation during environment
preparation, a real Python environment
lifecycle, unsaved buffers surviving split/merge and drag, submenu spacing and
keyboard navigation, collapsed panel corners, settings layout in all three native
themes, palette geometry, streaming Unicode and reading position, and reduced
motion.

Application adapter tests check argument construction, workspace boundaries and
trust requirements. They do not claim authenticated end-to-end sessions with all
seven external applications.

Native verification uses the actual frozen application, not the source interpreter:

- `dist/Zenit/zenit-python.exe --python-child tests/native_smoke_worker.py`:
  fifteen checks passed in the actual WebView2 runtime, including detached Forge,
  Lantern, live buffers, Monaco, native preview and extension integration.
- `dist/Zenit/zenit-python.exe --python-child tests/packaged_sessions_worker.py`:
  five checks passed. A real environment used the bundled Python interpreter,
  pip and debugpy, saved and restored its descriptor, and exposed all seven
  connection adapters from the frozen backend.
- `python tests/check_packaged_uninstaller.py --exe dist/Uninstall-Zenit.exe`:
  six checks passed with the final executable. The native uninstaller relocated
  itself, removed a read-only SDK file, and retained the profile and projects.
- `python tools/verify_native_package.py --integrity-only`: passed for the final
  Windows installer and portable ZIP. SHA-256 values match the release manifest;
  the installer contains the current application payload, launcher, uninstaller,
  toolchain executables and R12 interface files. The native GUI check above was
  already complete and was not repeated by this integrity-only pass.

The artifacts are `Zenit-0.5.4-R12-Windows-Setup.exe` and
`Zenit-0.5.4-R12-Windows-Portable.zip` in `dist`. Their source commit is
`17b9442500f8f2b1b4060129ced829e25292b781`; subsequent verification-report changes
do not alter the packaged application.

No signing or public release is implied by these checks.
